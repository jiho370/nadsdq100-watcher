## 1. 요약 — 가장 먼저 봐야 할 3가지

| 순위 | 문제 | 왜 치명적인가 |
|---|---|---|
| ① | **백테스트 성과가 통계적으로 믿기 어려울 만큼 좋다** (12개월 초과수익 +20%p, 승률 89.5%, MDD -1.8%, 샤프 1.6) | 이 숫자가 과최적화(overfitting)의 산물이라면, 그 위에 세울 0~10 점수 체계·개인화 시스템도 전부 "정교하게 틀린" 결과물이 된다. **가장 먼저 검증해야 할 항목.** |
| ② | **거래비용·세금·슬리피지가 백테스트에 전혀 반영되지 않은 것으로 보인다** | 월 2~3회 매매하는 실사용자 입장에서 한국 매도세만 왕복 기준 약 0.2%p, 여기에 스프레드·수수료가 더해진다. 백테스트 수익률과 "지호 님 계좌에 실제로 들어오는 수익률" 사이에 괴리가 생긴다. |
| ③ | **매수/매도가 이진적(사도됨/관찰/제외)이라 "얼마나 확신하는가"가 없다** | 지호 님이 요청한 0~10 추천강도는 단순 UI 개선이 아니라, "이 신호가 과거에 실제로 얼마나 잘 맞았는가"를 정량화하는 새로운 레이어다. ①이 선행되지 않으면 이 점수도 허상의 숫자가 된다. |

**권장 순서**: ① → ② → (③ 점수체계) → 한국 펀더멘털 팩터 보강 → (후순위) 개인화 시스템. 순서를 바꾸면 안 되는 이유는 6장에 있다.

## 2. 사용자 프로필에 맞춰 설계 원칙부터 재정렬

지호 님은 "10년 이상 장기투자자, 개별종목은 월 2~3회 매매"라고 하셨다. 그런데 현재 시스템은:

- 지수/코인 신호는 **매일** 갱신되고,
- 개별종목 매도 규칙(트레일링 -20%, 200일선 -3% 이탈)도 **매일** 새로 계산되며,
- 관찰→매수 전환 조건(20일선 회복, RSI≤70)도 **일 단위**로 판정된다.

즉 신호 생성 주기(일 단위)와 실제 매매 주기(월 2~3회) 사이에 10배 가까운 간극이 있다. 이 간극 자체가 문제는 아니지만("매일 확인하되 매매는 드물게"는 정상적인 장기투자 방식이다), **신호가 whipsaw(단기 노이즈로 인한 잦은 온오프 전환)를 만들면 장기투자자에게는 오히려 혼란만 준다.** 개선 방안(4.5절)에서 "일간 원신호 + 주간 확정 신호"를 분리하는 것을 제안하는 이유다.

## 3. 현재 알고리즘 진단 — 구조적 문제점

### 3.1 백테스트 신뢰도 — 가장 우선순위가 높은 이슈

`STRATEGY.md`에 인용된 수치(12개월 초과수익 +20%p, 승률 89.5%, MDD -1.8%, 샤프 1.6)는 개별주 팩터 전략치고 이례적으로 좋다. 참고로 학계에서 잘 검증된 모멘텀·퀄리티 팩터들의 장기 샤프비율은 보통 0.3~0.7 구간에 몰려 있고, MDD -1.8%는 주식형 전략에서는 거의 무위험자산 수준의 낙폭이다. 좋은 성과 자체가 잘못은 아니지만, 이 정도 수치가 나왔다면 아래 세 가지를 의심하고 검증하는 것이 표준 절차다.

- **다중검정 편향(멀티플 테스팅)**: Harvey, Liu & Zhu(2016, *Review of Financial Studies* 29(1), 5-68)는 지금까지 학계에 발표된 주식 수익률 예측 "팩터"가 300개가 넘는다는 점을 지적하며, 이렇게 많은 조합을 시도한 뒤 채택하는 구조에서는 t-값 2.0이 아니라 **3.0 이상**을 기준으로 삼아야 한다고 주장한다. 현재 시스템도 `backtest_weights.py`로 여러 팩터·가중치 조합을 탐색해 "가장 잘 맞는" 조합(`gross_margin×2 + accruals×2 + mom6×2 + mom12_1×1 + shareholder_yield×1`)을 채택하는 구조이므로, 이 문제에서 자유롭지 않다.
- **백테스트 과최적화**: Bailey & López de Prado(2014, *Journal of Portfolio Management* 40(5), 94-107)의 Deflated Sharpe Ratio, 그리고 Bailey, Borwein, López de Prado & Zhu(2017, *Journal of Computational Finance* 20(4), 39-70)의 "Probability of Backtest Overfitting(PBO)"은 "시도한 조합 수"와 "표본 기간"을 반영해 보고된 샤프비율을 깎아내리는 방법론이다. 현재 워크포워드 검증(IS 6개월 +9.73%p → OOS +9.88%p)은 방향은 맞지만, 검증 구간이 짧고(6개월) 단일 분할이라 통계적으로 약하다.
- **생존편향(survivorship bias) 가능성**: "미국: S&P500", "한국: 코스피200" 유니버스로 랭킹한다고 되어 있는데, 만약 **현재 시점의 지수 구성종목**을 과거 데이터에도 그대로 적용해 백테스트했다면(즉 지금 S&P500에 있는 종목들로 5~10년 전 성과를 계산했다면), 중간에 지수에서 탈락한(상장폐지·편출된) 부실 종목들이 애초에 표본에서 빠져 성과가 실제보다 부풀려진다.

**결론**: ①②③이 통제된 상태에서도 저 수치가 재현된다면 그때는 신뢰해도 좋다. 지금은 "재현 안 된 좋은 성과"에 가깝다.

### 3.2 팩터 가중치가 임의적 — 근거는 있지만 "왜 2배·1배인지"는 설명되지 않음

`gross_margin×2 + accruals×2 + mom6×2 + mom12_1×1 + shareholder_yield×1`의 정수 가중치는 백테스트로 "확정"했다고 되어 있지만, 개별 팩터 IC(정보계수)는 gp_assets(0.088) > gross_margin(0.075) > mom12_1 > cop(0.029) 순으로 문서에 나열되어 있다. IC 순위와 가중치 순위가 완전히 일치하지 않는데(예: mom12_1은 IC가 상대적으로 낮은데 가중치는 1), 이게 의도적 설계인지 그리드서치의 우연한 결과인지 문서만으로는 알 수 없다.

- **개선 방향**: Fama-MacBeth(1973) 방식의 횡단면 회귀로 각 팩터의 한계 기여도를 추정하거나, IC 기반 가중치(IC가 높을수록 큰 가중치, `IC/σ(IC)`로 정규화하는 IR-가중 방식)를 쓰는 것이 정수 가중치보다 재현 가능하고 설명 가능하다.
- 팩터 간 상관관계도 점검이 필요하다. `gross_margin`과 `accruals`, `shareholder_yield`는 서로 약하게 연관된 재무 건전성 지표라 다중공선성이 있을 수 있다. 직교화(orthogonalization)나 PCA로 중복 정보를 제거하면 가중치가 더 안정적으로 나온다.

### 3.3 시점정합성(point-in-time) 문제

SEC EDGAR 데이터를 쓴다고 되어 있는데, 재무제표는 **분기 마감일과 실제 공시일 사이에 수주~수개월의 시차**가 있다. 백테스트에서 "공시되기 전 시점의 데이터를 그날 이미 알고 있었던 것처럼" 사용하면(이른바 look-ahead bias) 실제로는 불가능한 정보 우위가 생겨 성과가 부풀려진다. 문서에는 이 부분에 대한 언급이 없다.

- **개선 방향**: EDGAR의 실제 공시(filing) 타임스탬프를 기준으로, "그 시점에 실제로 알 수 있었던 값"만 쓰도록 데이터 파이프라인에 지연(lag)을 명시적으로 넣어야 한다. 보통 분기 실적은 공시 후 최소 1거래일 지연을 적용하는 것이 관행이다.

### 3.4 거래비용·세금·슬리피지가 백테스트에 없다

2026년 기준 한국 증권거래세는 코스피 매도 시 0.05%(거래세)+0.15%(농특세)=0.20%, 코스닥 매도 시 0.20%(거래세만)이다. 손실이 나도 무조건 부과된다. 여기에 매수/매도 각각의 증권사 수수료, 호가 스프레드, 대형주 대비 상대적으로 큰 슬리피지(특히 코스피200 중소형주)까지 더하면, 월 2~3회 회전하는 개별종목 전략에서는 연간 수 %p의 비용이 조용히 수익률을 깎아먹는다. 미국은 SEC Fee가 매도금액의 0.00278% 수준으로 미미하지만, 매수 시 50%/2차 20일선 부근 등 **분할매수 자체가 매매 횟수를 늘리는 구조**라 누적 비용이 무시할 수준은 아니다.

- **개선 방향**: 백테스트에 왕복 비용을 명시적으로 반영(한국: 매도 시 0.20%+수수료, 미국: 매수·매도 각 수수료+SEC fee)하고, **총 수익률(gross)과 순 수익률(net)을 항상 나란히 보고**하도록 리포트 포맷을 바꾼다. 트레일링 스톱(-20%)이나 손절선처럼 "먼저 걸리는 것"이 기준인 규칙은 특히 잦은 손절이 비용을 누적시키므로, 순수익 기준 재검증이 중요하다.

### 3.5 리스크 신호가 "기대값"을 보여주지 않는다 (0~10 점수 부재의 근본 원인)

현재 5단계 상태판정표(🟢🔵🟡🟠🔴)는 카테고리형이다. "🔵 눌림목 분할 매수 = 기대값 최상 구간"이라고 서술은 하지만, 그 "최상"이 과거 데이터에서 평균 몇 %의 수익률과 몇 %의 승률로 뒷받침되는지는 시스템 어디에도 계산되어 있지 않다. 지호 님이 요청한 0~10 점수는 바로 이 공백을 메우는 작업이다 — 자세한 설계는 5장에서 다룬다.

### 3.6 포트폴리오 레벨 리스크 관리가 없다

미국 최종 매수 4종목, 한국 최종 매수 3종목을 매일/매주 독립적으로 뽑지만, **이 종목들이 서로 얼마나 겹치는 섹터·팩터에 노출되어 있는지는 점검하지 않는다.** 팩터 가중치가 모멘텀·수익성 위주이다 보니 특정 시기엔 후보 4~7종목이 전부 반도체·2차전지처럼 한 섹터에 몰릴 수 있다. 개별 종목 단위로는 규칙을 다 지켜도, 포트폴리오 전체로는 집중 리스크가 커질 수 있다는 뜻이다. 이 문제는 후순위 기능인 "보유종목 기반 개인화 진단"과도 직결된다(7장).

### 3.7 한국 종목 랭킹은 미국 대비 검증이 약하다 (이미 문서 9장에 인지되어 있음)

한국은 `z(12-1 모멘텀)×0.6 + z(52주 고점 근접도)×0.4`만으로 랭킹하고, 미국처럼 gross_margin·accruals 같은 펀더멘털 팩터의 IC 검증을 거치지 않았다. `SYSTEM_OVERVIEW.md` 9장에 이미 "조사 가치 있음"으로 적혀 있는데, 이 제안서에서는 이를 **정식 To-do로 승격**한다(4.7절).

### 3.8 AI 검증 레이어의 실효성이 측정되지 않는다

AI(sonnet + 웹검색)가 후보를 "매수유지/관찰강등/제외"로 판정하는데, 이 판정이 실제로 수익률을 개선하는지 검증하는 로직이 없다. AI가 제외한 종목과 그대로 뒀을 종목의 **사후 수익률을 비교하는 로그**가 쌓이지 않으면, AI 레이어가 알파를 더하는지 노이즈를 더하는지 영원히 알 수 없다.

- **개선 방향**: `output/ai_verdict_log.json` 같은 파일을 만들어 "AI가 제외한 종목의 이후 30/60/90일 수익률"을 계속 기록하고, 분기마다 "AI 제외군 평균수익률 vs 유지군 평균수익률"을 비교한다. 이 자체가 하나의 미니 백테스트가 된다.

## 4. 개선 방안 — 지표·근거·백테스트 방법론

### 4.1 백테스트 과최적화 방지 (최우선)

| 조치 | 방법 |
|---|---|
| 다중검정 보정 | Harvey-Liu-Zhu(2016) 기준 채택 시 t-값 3.0 이상 요구, 또는 시도한 팩터·가중치 조합 수를 기록해 Bonferroni류 보정 적용 |
| 성과 디플레이션 | Bailey & López de Prado(2014) Deflated Sharpe Ratio를 계산해 "이 정도 표본·시행 횟수에서 샤프 1.6이 통계적으로 유의한가"를 별도로 보고 |
| 견고한 교차검증 | 단일 IS/OOS 분할 대신 López de Prado(2018, *Advances in Financial Machine Learning*)의 **Combinatorial Purged Cross-Validation(CPCV)** — 여러 비인접 구간을 조합해 반복 검증, 구간 간 데이터 누수(purging/embargo)까지 처리 |
| 생존편향 제거 | 각 리밸런싱 시점에 **그 시점 기준 실제 지수 구성종목**(point-in-time index membership)을 사용 — 현재 시점 구성종목으로 과거를 되짚지 않기 |
| 시점정합성 | 재무 데이터는 EDGAR 공시 타임스탬프 기준 지연 적용 |

### 4.2 팩터 모델 고도화

- IC 기반 가중치(또는 Ridge/Lasso 회귀로 팩터 결합) — 정수 가중치(×2, ×1) 대신 통계적으로 추정된 가중치.
- 팩터 직교화로 gross_margin·accruals·shareholder_yield 간 중복 정보 제거.
- 이미 채택된 accruals 팩터의 근거를 명확히 인용: Sloan(1996, *The Accounting Review* 71(3), 289-316)은 발생액(accruals) 비중이 높은 이익일수록 지속성이 낮고, 이를 이용한 롱-숏 전략이 연 약 12%의 헤지수익을 냈다고 보고했다 — 현재 시스템의 accruals 채택은 이 문헌과 정합적이다.
- gross_margin·gp_assets 계열은 Novy-Marx(2013, *Journal of Financial Economics* 108(1), 1-28)의 "총이익/자산" 수익성 프리미엄과 같은 계열 — 역시 근거가 탄탄하다. 다만 Piotroski(2000) F-Score처럼 **재무 건전성 개선 추세**(전분기 대비 ROA·마진·부채비율 개선 여부)를 이진 스코어로 추가하면, 현재의 수준(level) 중심 팩터에 방향성(변화) 정보를 더할 수 있다.
- 재검증 주기는 현재 문서대로 분기~반기 유지, 단 매 재검증마다 PBO/DSR도 함께 계산해 로그로 남긴다.

### 4.3 거래비용·세금 반영 백테스트

- 한국: 매도 시 코스피 0.20%(거래세+농특세), 코스닥 0.20%(거래세) + 증권사 수수료 + 추정 슬리피지(코스피200 시가총액 하위 구간은 상위 구간보다 스프레드를 더 크게 가정).
- 미국: 매수·매도 각 수수료(브로커리지에 따라 상이, 무료 브로커 가정 시 SEC fee만) + 슬리피지.
- **분할매수 자체의 비용**도 반영: 2~3분할이면 매매 횟수가 그만큼 늘어난다.
- 리포트에 gross/net 수익률을 나란히 표기 — "백테스트가 보여주는 숫자"와 "실제로 계좌에 남는 숫자"의 괴리를 사용자가 직접 볼 수 있게 한다.

### 4.4 트레일링 스톱·이탈 기준 재검토

현재 -20% 트레일링은 Dai(2021) 등에서 제시하는 15~20% 최적구간의 상단에 위치한다. 월 2~3회 매매하는 장기투자자에게는 이 폭이 적절할 수 있지만, **연 단위 회전율과 손절 빈도를 함께 백테스트**해서 "고정 -20%"보다 "변동성 조정 트레일링"(ATR 배수 기반, 종목별 변동성이 다르므로 고정 %가 아니라 ATR×N배로 손절폭을 설정)이 더 나은지 비교해볼 가치가 있다. Moreira & Muir(2017, *Journal of Finance* 72(4), 1611-1644)와 Barroso & Santa-Clara(2015, *Journal of Financial Economics* 116(1), 111-120)의 변동성 관리(volatility-managed / managed-volatility) 연구는 정확히 이 방향(고정 손절 대신 변동성에 연동한 리스크 관리)을 지지한다.

### 4.5 신호 주기를 매매 주기에 맞추기

- **일간 원신호**(현재 방식 유지, 지수/코인 추세신호 등)와 **주간 확정 신호**(월~금 신호를 모아 금요일 종가 기준으로 재확인)를 분리해서, 이메일에는 "일간 참고용"과 "이번 주 확정 액션"을 구분 표기.
- 히스테리시스 확인일수(현재 3거래일)를 개별주 매수/매도 규칙에도 일관 적용해 whipsaw를 줄인다(현재는 지수/코인 신호에만 히스테리시스가 있고, 개별주 매도 규칙은 즉시 반응형).

### 4.6 포트폴리오 레벨 집중도 체크 (개인화 이전 단계에서도 가능)

수신자가 1명이던 지금도 구현 가능한 개선: 매수 후보 4~7종목을 뽑을 때 GICS 섹터 분산도를 계산해서, 특정 섹터 비중이 과도하면(예: 후보의 50% 이상이 동일 섹터) 리포트 상단에 "이번 주 후보는 반도체 섹터에 집중되어 있습니다" 같은 경고 문구를 자동 생성. 코드 규칙(섹터 캡)으로 후보 자체를 제한할지, 경고만 할지는 지호 님이 결정할 문제.

### 4.7 한국 펀더멘털 팩터 도입 (3.7절 후속)

현재 EPS>0, ROE≥8%, PER≤40은 필터일 뿐 랭킹에는 안 쓰인다. 미국과 동일한 gross_margin·accruals류 팩터를 다트(DART, 한국 전자공시) 데이터로 계산해 IC를 검증하고, 유의하면 한국 랭킹 공식에도 `추세 점수 + 펀더멘털 점수` 형태로 편입한다. `backtest_weights.py`와 동일한 워크포워드 절차를 한국 유니버스에도 적용.

## 5. 0~10 매수/매도 추천강도 점수 — 설계 상세

핵심 원칙: **이 점수는 "느낌"이 아니라 "과거 데이터가 보여준 기대값의 순위"여야 한다.** 임의의 가중합 공식으로 0~10을 만들면 그럴듯해 보일 뿐 근거가 없다. 아래는 데이터 기반으로 점수를 만드는 절차다.

**1단계 — 구성요소 산출** (모두 기존 시스템에 있는 신호를 재활용):
1. 팩터 랭킹 percentile (기존 `select_by_weights` 점수를 유니버스 내 백분위로 변환)
2. 추세/모멘텀 품질 (레짐 ON 지속일수, 12-1 모멘텀 크기, 52주 고점 근접도)
3. 밸류에이션/펀더멘털 percentile (한국은 4.7절 완료 후 추가)
4. 리스크 조정 (ATR 또는 60일 실현변동성 — 변동성이 과도하게 큰 종목은 감점)
5. 뉴스/촉매 보정 (AI 검증 결과를 **작은 폭의 가감점**, 예: ±1점 이내로만 반영 — AI가 점수 전체를 좌우하지 않도록 상한을 둔다. 이는 기존 시스템의 "AI는 종목을 추가할 수 없다"는 원칙과 같은 정신이다)

**2단계 — 과거 데이터로 캘리브레이션(가장 중요한 단계)**:
1~4를 합성한 복합 점수를 과거 전체 후보 풀에 대해 계산하고, 그 점수를 10분위(decile)로 나눈다. 각 분위별로 **실제 다음 1개월(또는 보유기간) 수익률의 평균·승률·평균손익비**를 집계한다. 이 분위별 실측 기대값 테이블이 있어야, "점수 8점은 과거 평균 몇 % 기대수익에 승률 몇 %였다"는 식으로 0~10을 정직하게 설명할 수 있다.

**3단계 — 검증(스코어가 진짜인지 확인)**:
점수 분위와 실현 수익률 사이의 Spearman 순위상관을 계산한다. 통계적으로 유의한 단조 관계(분위가 높을수록 기대수익도 높아지는 관계)가 나오지 않으면, 그 점수는 표시하지 않는다 — Harvey-Liu-Zhu(2016)식 경고를 스스로 적용하는 것이다. 이 검증을 통과한 뒤에만 이메일에 노출한다.

**4단계 — 표시 방식(예시)**:

| 점수 | 해석 (과거 분위 실측치 예시 형태) | 톤 |
|---|---|---|
| 9~10 | 과거 동일 분위 평균 수익률 최상위, 승률·손익비 모두 상위 | "강한 매수 후보" |
| 6~8 | 평균 이상, 다만 손실 케이스도 존재 | "매수 후보" |
| 4~5 | 평균 근처, 방향성 약함 | "관찰" |
| 0~3 | 과거 분위 성과가 저조하거나 표본 부족 | "제외/보류" |

매도(처분)에도 대칭적으로 0~10 "처분 시급도" 점수를 둘 수 있다 — 손절선 이탈폭, 모멘텀 악화 정도, 트레일링 스톱까지 남은 여유폭을 같은 방식으로 캘리브레이션.

**참고 — 포지션 사이징과는 분리할 것**: 점수를 그대로 매수 금액 비중으로 쓰고 싶은 유혹이 있는데, Kelly(1956) 기준 최적 베팅 비율은 이론상 최댓값이며 실전에서는 추정오차 때문에 그대로 쓰면 과도한 변동성을 만든다. 실무에서는 Thorp(2006)이 제안한 것처럼 **Kelly의 1/4~1/2만 사용하는 fractional Kelly**가 표준이다. 0~10 점수는 "확신도 표시"로, 실제 매매 비중은 기존 entry_plan.py의 분할매수 로직(하드코딩)이 계속 담당하는 구조를 권장한다 — "일관 패턴은 하드코딩, 변하는 것만 표시"라는 기존 철학과도 맞는다.

## 6. 검증 로드맵 (이 순서를 지켜야 하는 이유)

```
1단계: 거래비용·세금 반영 재백테스트
   └─ "진짜" 순수익률이 얼마인지부터 확인 (지금 숫자는 총수익 기준일 가능성)
2단계: 생존편향 제거 + 시점정합성 확보
   └─ 팩터 IC·가중치를 다시 계산 (1·2단계 후 숫자가 크게 바뀔 수 있음)
3단계: PBO / Deflated Sharpe Ratio로 통계적 유의성 재평가
   └─ 여기서 "승률 89.5%" 같은 수치가 얼마나 깎이는지 확인
4단계: 0~10 점수 캘리브레이션 + 단조성 검증
   └─ 1~3단계가 끝난 "진짜" 데이터 위에서 캘리브레이션해야 의미가 있음
5단계: 한국 펀더멘털 팩터 IC 검증 및 편입
6단계(후순위): 다중 사용자 개인화 시스템
```

1~3단계를 건너뛰고 4단계(0~10 점수)나 6단계(개인화)로 바로 가면, 겉보기엔 더 정교한 시스템이지만 속은 여전히 검증되지 않은 백테스트 위에 서 있는 상태가 된다.

## 7. (후순위) 다중 사용자 개인화 진단 시스템 — 설계 개요

현재는 1인 발송·JSON 파일 상태관리(`output/ai_holdings.json` 등) 구조라 여러 사용자로 확장하려면 구조 변경이 필요하다.

**7.1 데이터 입력**
- 사용자가 보유종목(티커, 수량, 평단가, 매수일)을 입력하는 경로 2가지 중 택1(또는 병행):
  - (a) 이메일 회신 파싱: 정해진 포맷("종목명 수량 평단가")으로 회신하면 파싱 — 구현이 간단하지만 오류 처리가 까다로움.
  - (b) 간단한 웹폼(Google Form 또는 경량 Flask 앱) → 스프레드시트/DB에 저장 — 초기 구현은 더 걸리지만 장기적으로 안정적.
- 지호 님이 프로그래밍 경험이 많지 않다고 하셨으니, 초기 버전은 **Google Sheets를 DB 대용으로 쓰는 방식**(gspread 라이브러리)을 권장 — 코드 복잡도를 낮추면서도 사용자가 직접 데이터를 확인할 수 있다.

**7.2 저장소 전환**
- 사용자 수가 늘면 JSON 파일보다 **SQLite**(단일 파일 DB, 별도 서버 불필요, 소규모에 적합)로 전환. 스키마 예:
  - `users(id, email, created_at)`
  - `holdings(user_id, ticker, market, qty, avg_price, updated_at)`
- GitHub Actions 러너는 매 실행마다 초기화되므로, 기존 `output/*.json`처럼 **SQLite 파일도 commit-back** 하거나, 이 시점부터는 외부 관리형 DB(예: Supabase 무료 티어)로 옮기는 것을 고려할 만하다.

**7.3 개인화 진단 로직**
- 사용자의 보유종목 각각에 대해: 이미 3.6~4절에서 설계한 매도 규칙(트레일링/이탈)과 0~10 처분 점수를 그대로 적용.
- 신규 추천 후보와 보유종목 간 **섹터/팩터 중복도** 체크(3.6절 로직 재사용) — "이미 반도체 비중이 높은데 추가로 반도체 종목을 추천하지 않기" 같은 조정.
- 포트폴리오 전체 관점: 총 주식비중, 현금비중, 종목당 비중이 지나치게 큰지(집중 리스크) 진단.

**7.4 비용 관리**
- 사용자별 개인화 문구 생성은 AI 서술이 필요한 부분이라 사용자 수가 늘면 비용이 선형으로 증가한다. 기존 시스템이 이미 쓰고 있는 **Batch API(50% 할인)**를 여기에 활용 — 발송 시각이 정해져 있으므로 실시간 응답이 필요 없어 배치 처리에 적합하다.
- 프로필 캐시(`gen_profiles.py`)처럼, "종목 설명"은 사용자 공통이라 1회 생성 후 재사용, "개인화 진단 코멘트"만 사용자별로 생성하도록 분리하면 비용을 최소화할 수 있다.

**7.5 프라이버시**
- 보유종목·수량 정보는 민감한 재무정보이므로 옵트인(명시적 동의) 방식으로 수집하고, 이메일 회신 파싱을 쓸 경우 발신 주소 검증(스푸핑 방지)이 필요하다.

## 8. Fable 5 핸드오프 가이드

이 문서를 그대로 Fable 5에게 전달하며 아래와 같은 순서로 요청하는 것을 권장한다(한 번에 다 시키지 말고 단계별로):

1. "`STRATEGY_UPGRADE_PROPOSAL.md`의 6장 로드맵 1~2단계를 구현해줘. 기존 `backtest_weights.py`에 거래비용(코스피 매도 0.20%, 코스닥 매도 0.20%, 미국은 SEC fee)과 생존편향 제거(point-in-time 유니버스)를 반영한 버전을 만들고, 기존 백테스트 결과와 나란히 비교해줘."
2. (1 완료 후) "3장의 PBO/Deflated Sharpe Ratio를 계산하는 스크립트를 추가해줘. `output/pbo_report.json`에 저장."
3. (2 완료 후) "5장 설계대로 0~10 점수 캘리브레이션 모듈(`score_calibration.py`)을 만들어줘. 분위별 실측 기대값 테이블을 `output/score_calibration.json`으로 저장하고, 단조성 검증(Spearman)이 통과하지 못하면 점수를 리포트에 노출하지 않도록 해줘."
4. (한국 팩터) "4.7절대로 DART 재무데이터 기반 한국 팩터 IC 검증 스크립트를 추가해줘."
5. (후순위) "7장 설계대로 SQLite 기반 다중 사용자 보유종목 관리 스키마와 개인화 진단 리포트 로직의 최소 버전(MVP)을 만들어줘."
